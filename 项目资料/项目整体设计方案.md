### 二、服务端架构

#### 依赖清单

```
express          Web 框架
@coze/api        Coze 官方 Node.js SDK
cors             跨域支持（开发阶段）
helmet           基础安全头
express-rate-limit  并发请求限流保护
```

#### 核心接口设计

**POST `/api/chat/stream`**
- 接收：`{ api_key, bot_id, base_url, conversation_id, messages }`
- 响应：`Content-Type: text/event-stream`
- 服务端调用 `@coze/api` 的 `client.chat.stream()`
- 按事件类型封装后转发，字段结构如下：

```
{ type: 'thinking', content: '...' }
{ type: 'answer',   content: '...' }
{ type: 'meta',     chat_id: '...', conversation_id: '...' }
{ type: 'done' }
{ type: 'error',    message: '...' }
```

**GET `/api/chat/messages`**
- 接收：`api_key, bot_id, base_url, chat_id, conversation_id`（query params）
- 调用 Coze message list 接口
- 返回：`{ thinking: '...', answer: '...' }`

#### 并发处理策略

每个 `/api/chat/stream` 请求在 Node.js 中是独立的异步上下文，`@coze/api` 每次调用创建独立的 stream 实例，天然隔离。服务端不维护任何全局 session 状态，所有上下文由客户端请求携带，支持无限并发路数（受限于 Coze API 的速率限制）。

添加 `express-rate-limit`，按 IP 限制单位时间内的请求次数，防止误操作导致 API Key 超额。

#### SSE 转发细节

- 设置响应头 `Cache-Control: no-cache`、`Connection: keep-alive`、`X-Accel-Buffering: no`（防止 Nginx 缓冲截断流）
- 客户端断开时监听 `req.on('close')` 及时销毁 Coze stream，避免资源泄漏
- 每条 SSE 消息格式：`data: {JSON}\n\n`

### 三、前端架构

#### 状态管理（store.js）

全局维护一个内存 Map，key 为 `conversationId`，value 为该路对话的运行时状态：

```
conversations: Map {
  convId → {
    thinkingBuffer: string,
    answerBuffer:   string,
    status: 'idle' | 'streaming' | 'completed' | 'interrupted',
    chat_id:        string,
    abortController: AbortController
  }
}
```

localStorage 只做持久化，结构如下：

```
coze_config
  → { apiKey, botId, baseUrl }

coze_conversation_list
  → [ { id, title, createdAt, updatedAt } ]

coze_conv_{id}
  → {
      messages: [
        {
          id, role, thinking, answer,
          status: 'completed' | 'interrupted',
          chat_id, conversation_id, ts
        }
      ]
    }
```

#### 流式接收（stream.js）

使用 `fetch` + `response.body.getReader()` 而非 `EventSource`，原因是需要 POST body 传递配置参数。每次发送消息创建独立的 `AbortController`，绑定到该对话的运行时状态，支持随时中断。

接收到 chunk 后：
1. TextDecoder 解码
2. 按 `\n\n` 分割 SSE 帧
3. 去掉 `data:` 前缀，JSON.parse
4. 按 `type` 字段分发：`thinking` 追加思考缓冲区，`answer` 追加正文缓冲区，`meta` 写入 chat_id/conversation_id，`done` 标记完成

#### Markdown 渲染策略（renderer.js）

- 引入 `marked.js`（CDN）和 `DOMPurify`（CDN）
- 增量渲染：每收到新 chunk，对整个 `answerBuffer` 调用 `marked.parse()`，输出经 `DOMPurify.sanitize()` 后写入 DOM
- 思考块同理，但内容为纯文本，不做 Markdown 解析，保持等宽字体显示
- 代码块：引入 `highlight.js`（CDN），`marked` 配置自定义 renderer，代码块自动语法高亮

#### 刷新恢复逻辑

页面 `DOMContentLoaded` 时执行：
1. 读取所有对话，检查 messages 中 `status === 'interrupted'` 的条目
2. 对这些消息渲染时，在 AI 消息气泡底部附加"拉取完整回复"按钮
3. 按钮点击 → 调用 `GET /api/chat/messages` → 用返回的 thinking/answer 覆盖原消息 → 标记为 `completed` → 更新 localStorage

### 六、关键组件交互说明

#### 思考过程折叠块

- HTML 使用原生 `<details>` + `<summary>` 实现，无 JS 依赖
- `<summary>` 显示"▶ 思考过程"，展开后箭头旋转 90°（CSS `details[open] summary` 控制）
- 流式输出期间：JS 强制设置 `details.open = true`，并移除用户手动折叠的能力（pointer-events: none）
- 流式完成后：恢复可交互，默认执行 `details.open = false` 收起
- 思考块内文字为等宽字体，文字色为次色 `#6B6B6B`，背景 `#F7F5F0`，左侧 3px 主色竖线作为装饰

#### 流式光标

- 用 CSS `::after` 伪元素实现 `▌` 闪烁效果
- 仅在 `status === 'streaming'` 时挂载对应 CSS class
- 思考区和正文区各自有独立的光标，当前活跃输出的区域显示，另一区域不显示

#### 拉取完整回复按钮

- 仅在消息 `status === 'interrupted'` 时渲染
- 样式：小号、边框按钮、主色文字、↻ 图标前缀
- 点击后：按钮变为 loading 态（旋转图标 + "获取中…"），禁用再次点击
- 成功后：按钮消失，消息内容被完整内容替换，右上角出现短暂"已补全"的 toast 提示
- 失败后：按钮恢复可点击，tooltip 提示错误原因

#### 并发状态指示器

- 位于右侧顶部标题栏右侧
- 当前有 N 路流式请求进行中时，显示 `● N 个对话流式中`（主色圆点 + 文字）
- 全部完成后隐藏
- 点击可展开显示正在进行中的对话列表，便于快速跳转

#### 输入区域

- `<textarea>` 自动扩展高度：监听 `input` 事件，重置高度再设为 `scrollHeight`，最大高度限制为 6 行
- Enter 发送，Shift+Enter 换行，底部提示文字说明
- 流式进行中：发送按钮替换为红色"停止"按钮，点击调用 `AbortController.abort()` 中断当前对话流
- 中断后当前消息状态标记为 `interrupted`，显示拉取按钮

#### 配置保存

- 点击保存后，输入框边框变绿色（`#4ABA8A`），持续 1.5 秒后恢复，无弹窗打断
- API Key 字段默认 `type="password"`，右侧眼睛图标切换明文/密文
- 服务区域下拉框选项：`国内版 (coze.cn)` / `国际版 (coze.com)`

### 七、异常处理与边界情况

| 场景 | 处理方式 |
|---|---|
| 未配置 API Key 发送消息 | 输入框下方红色提示"请先配置 API Key"，自动滚动到配置区 |
| Coze API 返回错误 | SSE 推送 `{ type: 'error', message }` → 气泡底部显示红色错误文案 |
| 网络断开 | fetch 抛出异常 → 标记 interrupted，显示拉取按钮 |
| localStorage 接近上限 | 写入前检查剩余空间，不足时提示用户清理最早的对话 |
| 空对话发送 | 发送按钮 disabled，输入框轻微抖动动画提示 |
| 对话列表为空 | 显示空态插画（SVG）+ 引导文案"点击左上角新建对话" |

### 八、实现顺序建议

1. **服务端骨架**：Express + 静态文件托管 + `/api/chat/stream` 接口（先验证 Coze SDK 流式调用）
2. **前端基础布局**：HTML 结构 + CSS 三栏布局，无交互
3. **store.js**：localStorage 读写封装，数据结构验证
4. **单路流式对话**：打通一次完整的发消息 → 流式接收 → 渲染链路
5. **思考块渲染**：接入 thinking 类型事件，实现折叠组件
6. **Markdown + 代码高亮**：接入 marked.js + highlight.js
7. **对话列表与切换**：侧边栏历史记录，localStorage 持久化
8. **并发支持**：多路 AbortController，状态 Map 管理
9. **中断恢复**：interrupted 状态检测，拉取接口对接
10. **配置面板**：环境切换下拉，保存逻辑
11. **细节打磨**：空态、错误处理、loading 态、toast 提示
